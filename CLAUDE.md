# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

FLAP (Fortran command Line Arguments Parser for poor people) is a pure Fortran library for building CLIs, inspired by Python's `argparse`. It supports optional/required/boolean/positional/list arguments, mutually exclusive groups, nested subcommands (groups), environment-variable fallback, and automatic help/usage/man page/bash completion/markdown generation.

Roadmap: GitHub issue **#125** is the authoritative consolidated implementation plan (bug register, error-code registry, phases 0–5, release train v1.3.0 → v2.0.0 → v2.x). The per-library issues #1, #11, #25, #77, #78, #113 hold the detailed designs and test tables; where they disagree with #125, #125 wins.

## Build Commands

FoBiS (CLI `fobis`, 3.8+) is the primary build tool and the one used in CI. Use the long-form flags (`--mode`, `--ex`, `--coverage`); FoBiS 3.8.22 still accepts the legacy single-dash forms, but new scripts, rules and docs use the long form.

```bash
fobis fetch                                  # fetch PENF and FACE into src/third_party/ (pinned by fobos.lock)
fobis build --lmodes                         # list modes
fobis build --mode tests-gnu                 # build all tests into exe/
fobis build --mode tests-gnu-debug           # debug tests (-fcheck=all, coverage flags)
fobis build --mode static-gnu                # static library
fobis clean --mode tests-gnu-debug           # needed when stale gcov objects in exe/obj break the debug link
fobis rule --ex delexe                       # wipe exe/ (fobis clean keeps executables); do it when switching modes
fobis build --mode tests-gnu-r16p            # debug tests with -D_R16P: real quad precision (R16P = real128)
bash scripts/run_tests.sh                    # run every binary in exe/ (exit 0 = PASS; *_xfail_* must exit non-zero)
fobis rule --ex makedoc                      # API docs (formal) + VitePress site
```

Modes: `shared-gnu`, `static-gnu`, `shared-gnu-debug`, `static-gnu-debug`, `tests-gnu`, `tests-gnu-debug`, and the same six for `intel`, plus `static-nvf` and `tests-gnu-r16p`. All test modes share `exe/` (hard-coded in `scripts/run_tests.sh`), so wipe it with `fobis rule --ex delexe` when switching modes.

Alternative build systems (kept working, not the reference): `fpm build` / `fpm test <name>`, `make`, `cmake -B build && cmake --build build`. Their source/test lists are explicit and can drift from the tree:
- `fpm.toml` has `auto-tests=false`: every new test needs a `[[test]]` entry;
- the FACE/PENF `rev` pins in `fpm.toml` must match the commits in `src/third_party/fobos.lock` (update both together).

## Tests

Tests are standalone programs in `src/tests/flap_test_*.f90`, and every one asserts (a failed check ends with `error stop`, exit status 1). Most example-derived tests have two modes: **with arguments** they are the original example program (parsing the real command line); **without arguments** (how `run_tests.sh`, fpm and ctest run them) they check their scenarios in-process with `parse(args=...)`, capturing FLAP messages. Known bugs are asserted as they behave today, with a `! Bnn (#125)` comment: the fix must flip that assertion. New tests must assert: use `src/tests/flap_test_utils.F90` (`assert`, `assert_equal`, `assert_contains`; `capture_open`/`read_back` to capture FLAP output via `init(usage_lun=, error_lun=)`; `reinvoke`/`child_case` to re-run the test as a child process for environment variables, stdin, exit statuses and `--help`/`--version`). `flap_test_harness.f90` is the reference example. Generated outputs (usage per group, man page, markdown, bash completion, `<group> --help`) are pinned by `flap_test_golden` against `src/tests/golden/`; after an **intended** output change regenerate them with a reference compiler (`FLAP_TEST_GOLDEN_UPDATE=1 ./exe/flap_test_golden`, run from the repo root) and review the diff. The files keep significant trailing blanks (see `.gitattributes`). A new test also needs a `[[test]]` entry in `fpm.toml`; CMake and FoBiS pick it up automatically. Completion scripts are checked by running them: `flap_test_shell_completion` sources the bash script and calls its function through a driver script (bash is always there), and checks zsh/fish/pwsh only when the shell is on `PATH` (the matrix `fobis` jobs install zsh and fish, pwsh is preinstalled; locally, unpack zsh/fish with `apt-get download` + `dpkg -x` and pwsh from its release tarball, set `PATH`/`FPATH`/`FLAP_TEST_FISH_FUNCTIONS`, and run pwsh without `ulimit -v`: .NET reserves more virtual memory than the cap). The bash script is registered with `complete -o default` (file-name fallback, a D12 exception); the zsh script is the same script behind `bashcompinit`, whose `compgen` does not filter by the current word (zsh's `compadd` does).

CI: `.github/workflows/ci.yml` (gcc-14 coverage) and the other files listed by `fobis scaffold list` are scaffold-managed (overwritten by `fobis scaffold sync`): do not edit them. Project-specific jobs go in `.github/workflows/matrix.yml` (gfortran 13/14/15 + `tests-gnu-r16p`, the gfortran-16 trunk snapshot allowed to fail, fpm/CMake/make builds).

Reference compilers: gfortran 13 and 14; the suite also passes with gfortran 15 and the 16 trunk.

## Architecture

### Module Dependency Chain

```
flap.f90                                         ← public interface (use this in consuming code)
├── flap_menu_t.F90                              ← interactive menus (opt-in; the parser never uses it; utils, PENF, FACE)
└── flap_command_line_interface_t.F90            ← main CLI type
    └── flap_command_line_arguments_group_t.f90  ← groups / subcommands
        ├── flap_config_m.f90                    ← INI configuration file reader (set_config)
        └── flap_command_line_argument_t.F90     ← individual argument
            ├── flap_object_t.F90                ← base class (error handling, common metadata)
            ├── flap_utils_m.f90                 ← string helpers (tokenize, unique, csv_split, ...)
            ├── PENF                             ← numeric kinds, cton/str
            └── FACE                             ← ANSI colours
```

All library source is in `src/lib/`. Dependencies (PENF, FACE) are fetched with `fobis fetch` into `src/third_party/`; they are not git submodules.

### Key Types

| Type | File | Role |
|------|------|------|
| `command_line_interface` | `flap_command_line_interface_t.F90` | Top-level API: `init`, `add`, `add_group`, `parse`, `get`, `get_varying`, `usage`, `save_*` |
| `command_line_arguments_group` | `flap_command_line_arguments_group_t.f90` | Named group of CLAs: subcommands and mutually exclusive groups; token-level parsing |
| `command_line_argument` | `flap_command_line_argument_t.F90` | Single argument: switch, abbreviation, action, default, nargs, choices, envvar; value casting |
| `object` | `flap_object_t.F90` | Base class: error code/message, help, examples, progname |

### Invariants that are easy to break

- Arguments are untyped until `get`: values are stored as strings and cast in `get` via `class(*)` + `select type`.
- List values are stored as `v1||!||v2||!||` (`LIST_SEP` plus a trailing separator; sanitized defaults have no trailing one). Only the list API of `flap_utils_m` knows the format: `list_push` (parser), `list_items`/`list_count` (every list getter), `list_join` (usage). `list_items` relies on `tokenize` dropping the trailing empty token: do not "fix" it.
- Switch names are matched only by `command_line_argument%match_token` (decision D1 of #125, rule 1: exact, the negation `switch_neg` of a flag pair included; `match_negation` tells which; the names are compared by `same_name`, in any case with `case_insensitive`, F14) and `match_inline_token` (rule 2: `NAME=VALUE`, built on rule 1); the parser and its look-ahead (`is_switch_token`) use the latter, while `is_defined`/`is_passed`/`value_arity` stay exact. Never compare `switch`/`switch_ab` directly: inline values, `-vvv`, negation and case folding extend the matcher, not its callers.
- An explicitly empty command line value (`--opt ""`, `--opt=`, an empty `append` occurrence) is the empty string (D17, reversed in step 2.11); a numeric option fails its cast in `get`. An empty or blank environment/configuration value is **unset** instead (F07/F08).
- Flag pairs (F11, `switch_neg`): the group parse records the last spelling in `is_negated` and the value of a flag passed on the command line is `flag_value()` (getters and `value_text`), never a literal `.true.`/`.false.`. The last spelling wins (D5); each spelling once (`is_pair_override`, `pair_passed`), both reset by `reset_parse`.
- "Did you mean" (F10): the one unknown-argument path of the group `parse` appends `suggestions` (`flap_utils_m`, Levenshtein similarity >= 0.6, at most 3) to `ERROR_UNKNOWN`; candidates are the group's CLA `names()` (visible switch, abbreviation, negation) for a switch-like token, the `commands` argument (names and aliases, passed by `parse_core` for the top level only) otherwise.
- `copy_options` (F21, D14) copies named options of a group into another by intrinsic assignment of the CLA (every definition component, automatically), then resets the runtime state (`is_passed`, `source`, `val = def`, `is_negated`, `pair_passed`, `error`): a new **runtime** component must be reset there too. A generated envvar (`is_auto_envvar`) is generated again for the target group. Builtins (print actions, `--`) and positionals are never copied; group-level definitions (exclusive sets) are not copied.
- Maps (F18, `is_map`, `map_keys`): a map is a store list (`nargs`) or an append whose items are `KEY=VALUE` (split at the first `=`); stored as any list. `check_map_consistency` (at `add`) checks the definition and the default pairs; the group `check_maps`, called by `parse_core` after the alternate return (top level, commands called), checks the resolved pairs whatever their source. `get_map`/`get_map_value` (CLI, through `map_cla`) read `stored_list()`; `get_map_value` converts with `get_cla_from_buffer`. A map accepts an inline `--set=a=1` (one pair), unlike other lists.
- Numeric ranges (F05: `range_min`/`range_max` strings, `min_open`/`max_open`/`clamp`) are checked by `check_range` after every conversion in `get` (scalar, count, and after `check_choices` in every list getter), with the value's text for the message; integers compared in I8P, reals in their kind; bounds are read quietly (`read_real`/`read_integer`, not `cton`, which prints).
- `nargs='*'` passed alone stores an empty list (D21, step 2.12; the default only when absent); the varying getters return an empty list as an allocated size-0 array (`check_list_size` false without error → `Nv = 0`).
- Positionals are looked up by their **declared** `position` (`positional_index`), never by an index into the CLA list or by token position.
- Builtins (`--help`, `--version`, `--markdown`, `--`, with `man_option` the top-level `--man` (F29: action `PRINT_MAN`, status −8, dispatched after markdown), and with `completion_options` the top-level `--show-completion`/`--install-completion`, F24: actions `SHOW_COMPLETION`/`INSTALL_COMPLETION`, parsed as `store*`, dispatched after help/version/markdown/man) are recognised by the CLA `is_builtin()` (the hidden `--` by its switch): `provenance` and `copy_options` skip them, and a new builtin action goes there. They are added by `ensure_builtins`: `parse` calls it, and every output method (`usage`, `signature`, `save_*`) works on a copy with the builtins, so its output is the same before and after `parse`. A new output method must follow the same wrapper + `*_core` pattern.
- The environment is read only through `read_env` (`flap_utils_m`), whatever the value length; `flap_test_envvar` fails if another library file calls `get_environment_variable`. Every call passes `ignore=` the CLI `ignore_env` (F20), which reaches the groups as a `parse` argument, like `ignore_unknown_clas`.
- What an error prints after its message (F27, `init(usage_on_error=)`): only the missing required option and the required exclusive set print a help (the group's, through the group routines, whose `print_usage` is true only for `'full'`); with `'usage'` the CLI prints the first line of its own `usage(g=)`, the one `--help` shows (`print_usage_line`, after the loop that failed). A new error that prints a help must follow the same choice.
- `cli%add` reports only its own definition: it resets the CLI error and the one the new CLA inherits through `assign_object` (B34). A group error set by an invalid exclusive set (104) persists on purpose, so that `parse` fails.
- `parse` only guards (already parsed) and returns the error; the stages live in the private `parse_core`, and `is_fatal` decides whether an error stops them (an ignored unknown argument does not). Every error message starts with `object%error_prefix(pref)`.
- Group (command) names are resolved only by the private `group_index` (-1 when there is no such group, 0 is the top level `''`; in any case with `case_insensitive`), through the group's `is_named` (its name or an alias, F19: `aliases` are `flap_string`); `is_defined_group` wraps it. Outputs list a command with `names(sep)` (help `, `, completion words ` `, `case` pattern `|`); a stored group name (`m_exclude`) is always the canonical one. `add_group` reports an invalid alias as `ERROR_GROUP_ALIAS`, kept on the group (as 104) so that `parse` fails. `case_insensitive` (F14) is an `object` component: it reaches the groups and the CLAs through `assign_object` when they are created, so `init` must come before `add`. Aliases (F19) extend the resolver, not its callers. A command is passed at most once: `get_clasg_indexes` returns the first repetition (name or alias; B36), which `parse_core` reports as `ERROR_COMMAND_REPEATED` (1013) right after the definition checks, before the statuses.
- An argument has one renderer per output: `signature_usage` (usage text), `completion_words` (bash word list), `completion_values` (bash `prev` test) and `completion_fish` (fish `complete` lines, called through the group's `completion_fish`) and `completion_powershell` (entries of the PowerShell options table, through the group's `completion_powershell`); `signature` only dispatches. Write a backslash as `achar(92)`, never as a literal (nvfortran reads it as an escape without `-Mbackslash`). Every completion script is built as text by `completion_script(shell)` (`bash_script`, `fish_script`, `powershell_script`) and written by `write_script`; the `save_*` methods and the completion builtins only call them. The value placeholder of the usage line and of the help lines (`usage`, also man page and Markdown) is always `placeholder()` (the `metavar`, F12, else `KEY=VALUE` for a map, else `value`): never write a `value` literal. A rendering change (metavar, `...`, `--x/--no-x`) goes into `signature_usage`, never into the completion renderers.
- Mutually exclusive sets (`set_mutually_exclusive_switches`, F03) are stored per group as lists of **switch names**, never as CLA indexes: adding a positional inserts it into the CLA list and shifts the indexes. They are checked by `check_exclusive_sets` in the post-parse stage of `parse_core` (after the statuses and the required check, E4); explicit sources count (`has_value`), and a member on the command line sends the env/config values of the others back to their defaults (D2, E3), and rendered once by the group `signature` as `(a | b)`/`[a | b]` with `signature_usage(bare=.true.)`.
- Every CLA value has a `source` (`SOURCE_COMMANDLINE` < `ENVIRONMENT` < `CONFIG` < `DEFAULT` < `NONE`, R chain of F06). The getters and the required check use `has_value()` (`source < SOURCE_DEFAULT`), never `is_passed`, which keeps its meaning "seen on the command line". The source of a parsed value is set **while parsing** (where `is_passed` is set; `SOURCE_ENVIRONMENT` in the envvar branch), so it survives a parse stopped by an error; `resolve_values` (CLI `parse_core`, after the statuses, before the required check) only settles the other CLAs (default or none). `reset_parse` resets it. `get_source`/`provenance` (CLI) only read it; `provenance` renders values with `value_text()` and names the config file from `config_used` (set by `load_config`).
- The environment is a value source (F07): the bare switch reads its variable while parsing, an absent option reads it in `resolve_values` (set and not blank: `set_source_value`, which also maps the flag words `yes/no`, `on/off`, ... to `.true.`/`.false.`). Flags take their constant value only when passed on the command line (`source == SOURCE_COMMANDLINE`); otherwise the getters read the stored value (environment or default). A list (`nargs`) reads its variable as one CSV record (`csv_split`, `flap_utils_m`: a separate splitter, never `tokenize`), stored with `list_push`; its bare switch follows `nargs`, not the single-value env branch. The configuration file (`set_config`, F08) is loaded by `load_config` in `parse_core` after the statuses, into a local `config_file` passed to `resolve_values` (environment first, then the file): it is not a CLI component. Keys are `config_key()` (switch without dashes), sections are group names; only `takes_config_value()` options accept one. `act='config'` is stored as a `store` CLA with `is_config` (so every store path handles it); `load_config` picks the file: that option's command line or env value (must exist), else `set_config`, else its default (skipped if missing). Path checks (F09: `must_exist`/`readable`/`writable`/`allow_dash`) run in `resolve_values` after the values are settled (`check_paths`: top level always, commands only when called), with `inquire` and an `open` probe that writes nothing; never probe with a write (an empty non-advancing write appends a record end). nvfortran 26.5 opens a read-only file for writing without error: `flap_test_path` pins that case per compiler (`compiler_version()`). Deprecation (F13: `deprecated` of a CLA or a group, allocated means deprecated) warns in `warn_deprecated` (CLI `parse_core`, after `resolve_values`, before the required check): an option only for sources command line/environment, a command when called; never an error. An alternate action (F16, `act='alternate'`, a flag) is detected in `parse_core` right after the statuses: `load_config(check=.false.)`, `resolve_values(check_paths=.false., lenient=.true.)`, deprecation warnings, then `STATUS_ALTERNATE`, skipping required, sets, pairwise `exclude` (now a validation-stage group check, no longer in the group `parse`) and group exclusion (the D4 list). A new validation must be placed after that return. `init(auto_envvar_prefix=)` fills the `envvar` of eligible options in `cli%add` (`envvar_name`), before the argument checks: an option added before `init` or through the group directly gets none.
- The menu module (`flap_menu_t`, F23, Phase 5 of #125, the wmenu plan of #78) is opt-in: no parser module (`flap_command_line_*`) may use it (`flap_test_menu` T0.1 greps for it). It owns no unit (the caller's `input_unit`/`output_unit`/`error_unit`, defaults the standard ones) and never stops; the end of the input is `ERROR_MENU_EOF` at once (never retried). Lines are read by `read_line` (`flap_utils_m`, shared with `flap_config_m`: any length, a last line without line end is a line). Its errors are the 2000–2099 range; each is written as `error: ...` on the error unit and returned.
- **gfortran bug (13–16):** a *section* of a deferred-length character array (`a(2:3)` with `character(len=:), allocatable :: a(:)`) passed to an assumed-shape `character(*)` dummy arrives starting at the first element of the whole array. Pass a whole-array copy instead (see the group call in `parse`).
- **nvfortran 26.5 bug (B33 of #125):** copying a derived type with a `character(len=:), allocatable :: a(:)` component writes past the allocation. Never add such a component: store arrays of strings as `type(flap_string), allocatable :: a(:)` (`flap_utils_m`; `a(i)%s`), as `examples` and the CLI `args` do. Library `stop`s go through `quiet_stop` (nvfortran rejects `stop, quiet=` and prints `FORTRAN STOP` on a plain `stop`). A write whose output list calls a function doing I/O itself (e.g. `usage`, whose builtins `add` reaches PENF's internal writes) loses its whole output under nvfortran 26.5: print FLAP-built text through `write_text(lun, text)` (`flap_utils_m`), never `write(lun,'(A)') self%usage(...)`. A second nvfortran 26.5 bug is in the **caller**: a variable passed to a `class(*)` dummy (every `get`) from several call sites of one scope (host-associated uses in internal procedures included) gets its descriptor set up at one site only, so a call executed before the first site in the source sees it uninitialised (value not set, or a crash). In tests, give each `get` call site its own variable (a local in each helper); with that, nvfortran passes the whole suite. The same bug hits an allocatable array passed back through several call sites (`menu%run(choices)` through a test helper: the caller keeps the old descriptor): check such results inside the helper, on its local.
- **gfortran 16 trunk (r16-8100) miscompilation:** in CLI code, a read of a `flap_string` array component of a group (`allocated(self%clasg(g)%examples)`, `...%aliases`) sees garbage bounds of `clasg` (out of bounds, or a crash); an array constructor growing an array of `flap_string` (`a = [a, flap_string(x)]`) crashes too. Read such components only through group methods (`has_examples`, `examples_text`, `name_count`, `name_of`, `names`, `has_alias`), and size such arrays first, filling them by element. The five tests that failed with gfortran 16 up to step 3.6 (copy, golden, no_args_is_help, raise_error, standalone, taken for a CLI miscopy, B17/B33) all went through the command help's `examples` read: since step 3.7 the whole suite passes with gfortran 16 (the CI job stays allowed to fail: a trunk snapshot).
- **gfortran 13.3 / 14.2 bug** (Ubuntu 24.04 default compilers; fixed in 13.4 and 14.3): inside `type is(character(*))` on a `class(*)` *array* dummy, element assignment uses a wrong element length. Delegate to a helper with a plain `character(*)` array dummy (see `get_cla_list_character`). CI covers these versions: the fobis gfortran-13 job and the cmake/fpm/make jobs use the Ubuntu archive compilers.
- Whole-object copies use intrinsic (deep) assignment: the types have no `assignment(=)` overloads. The one explicit copy is `object%assign_object` (the object part only): a component added to `object` must be added there too, and `flap_test_copy` fails otherwise.

### Preprocessor

**Never write a literal with the `_R16P` kind suffix** (`1._R16P`, `0.25_R16P`) in a preprocessed file (every file: the builds pass `-cpp`): with `-D_R16P` the preprocessor expands the `_R16P` of the suffix to `1` (`0.25_R16P` becomes `0.251`, a default real). Write `real(x, R16P)` (B35: `knd=1._R16P` made the quad `get` convert in single precision). PENF has the same pattern (third party). `.F90` files are preprocessed, `.f90` are not. Quad precision is gated on `#if defined _R16P` in both FLAP and PENF. The fobos templates and the CMake support check define `-D_R16P_SUPPORTED`, which **does not** enable that branch: with the current build files `R16P` aliases `R8P` and the quad-precision code is never compiled. Define `-D_R16P` to compile it (mode `tests-gnu-r16p`).

### `get` Overloading

`command_line_interface%get` covers every PENF kind (`R16P`, `R8P`, `R4P`, `I8P`, `I4P`, `I2P`, `I1P`), `logical` and `character`, scalar and fixed-size arrays; `get_varying` returns allocatable arrays for `nargs='+'/'*'` lists.
